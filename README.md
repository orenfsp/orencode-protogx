## Запуск с Docker Compose

Нужны Docker с Compose. Для локальных frontend-проверок нужны Node/npm,
для Playwright — установленный Google Chrome. Подробности: [быстрый старт](docs/team/QUICK_START.md).

Из корня в PowerShell создайте локальную конфигурацию, если её ещё нет:

```powershell
if (-not (Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
docker compose up -d --build --wait
docker compose ps
```

Перед первым запуском задайте в локальном `.env` свои `POSTGRES_PASSWORD` и
`DJANGO_SECRET_KEY`. Фиктивный seed разрешён только при
`DJANGO_DEBUG=1`, `DEMO_SEED_ENABLED=1`, `DEMO_ENVIRONMENT=local` и локальном
хосте БД. При запуске API применяет миграции и, если seed разрешён, вызывает
`seed_demo`. Иначе seed пропускается. Существующие пароли повторный seed сохраняет.

Стандартные адреса: сайт `http://localhost:3000`, API health
`http://localhost:8000/api/v1/health/`, Swagger `http://localhost:8000/api/docs/`,
схема `http://localhost:8000/api/schema/`, Mailpit `http://localhost:8025`.
БД хранится в именованном volume; удаление volume стирает данные.

Для дополнительных фиктивных записей:

```powershell
docker compose exec -T api python manage.py seed_optional
```

`seed_optional` сначала вызывает `seed_demo`, затем добавляет группы,
демонстрационные правила, наблюдателя министерства и OIDC-клиент.
Подготовка RSA/Fernet ключей и отдельного тестового OIDC-сайта описана в
[optional-demo.md](docs/optional-demo.md). Обычные кабинеты не требуют OIDC-ключа.

## Где проверить функции

1. `/dashboard` — четыре кабинета и переключение назначенных ролей;
   `/profile` — РУСАДА, `/coach-links` — запрос/подтверждение/история связи;
   согласия и их история доступны в кабинете.
2. `/competitions` — справочники, черновик, ЕКП/региональный план, положение,
   этапы, приём и модерация заявок, судейские должности, результаты,
   версии протокола. `/my-competitions` — события текущей роли.
3. `/history` — собственные опубликованные результаты, личная выписка и XLSX.
4. `/qualifications` — разряды/категории, основания, заявления, решения,
   приказы, сроки и исправления истории. ЕВСК — Единая всероссийская спортивная
   классификация; подсказки по ней требуют проверенных правил, которых сейчас в БД нет.
5. `/registry`, `/analytics/participation` — реестры, исторические периоды,
   динамика за два года и больше, разрезы и XLSX. Сумма разрезов может отличаться
   от общего числа уникальных людей; методика доступна в выгрузке.
6. `/ratings` — сезон/дисциплина, баллы, коэффициент 1.2 и источники;
   `/teams` — ручной состав, порядок, список сборной и проект приказа PDF/DOCX.
7. `/services` — вход в Д1–Д12: ФСП ID, интеграции, группы, аттестация,
   апелляции, показатели, личный путь, премии, министерство, QR-справки,
   навигатор и судейские документы. [Статусы по каждому сценарию](docs/case-optional-traceability.md).

Основной inbox API — `/api/v1/notifications/`, дополнительный —
`/api/v1/optional-notifications/`. Постоянный worker обрабатывает обе очереди
и напоминания премий. SMTP/Mailpit проверен локально; реальный внешний
почтовый ящик отдельно не проверялся. Webhook доставляется отдельной командой.
[Настройка уведомлений](docs/notifications.md), [внешние контракты](docs/optional-integrations.md).

Фиктивные аккаунты и пароль для локального стенда: [demo-scenarios.md](docs/demo-scenarios.md),
наблюдатель/дополнительные сценарии: [optional-demo.md](docs/optional-demo.md).
Регистрация выдаёт роль спортсмена; остальные роли назначает доверенный администратор.

## Сквозной показ перед защитой

Федерация создаёт соревнование → спортсмен подаёт заявку → федерация одобряет
и назначает судью → ввод/проверка результатов → публикация протокола →
результат в истории и рейтинге → ручной состав сборной → документ.
Дополнительно покажите двухлетний XLSX и QR-проверку без авторизации.
ФСП ID требует отдельного тестового клиента; одна страница настроек не заменяет
показ входа с другого сайта.

`seed_optional` и работающий тестовый OIDC-клиент.

## Известные ограничения

- С3: возраст и дисциплина тренерской связи проверяются; запрета подачи
  спортсменом заявки на отсутствующую в его истории дисциплину нет.
  Бизнес-правило требует уточнения по формулировке критериев.
- Т2: полноценные демо-результаты есть по двум дисциплинам из шести.
- Д3: зачисление в группу не создаёт периоды основного реестра и не меняет
  общий отчёт. Для Д6 отчёты групп и реестра доступны отдельно; их согласованное
  объединение и предотвращение двойного счёта ещё не реализованы.
- Д4/Д7/Д8: нормативы, путь и ставки премий демонстрационные.
- Шаблоны протоколов и судейских документов не приняты по заданным образцам.
- Полная ручная визуальная приёмка всех новых дополнительных форм не завершена.
- Реальная проверка личности представителя и официальное нормативное
  соответствие не заявляются; государственные интеграции исходный кейс не требует.
