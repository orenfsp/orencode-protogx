# Поиск спортсменов и история изменений

Реализация `223bebe28ac7fc1f5e4244f42d0e642b68fd3bdd`, ветка `codex/mandatory-case-completion`.

## Поиск и запрос связи

На `/coach-links` тренер вводит минимум три символа ФИО, выбирает одну из шести дисциплин и запрашивает связь. Спортсмен подтверждает её в своём кабинете. Поиск выдаёт не более 20 совпадений: только ID и ФИО активного спортсмена с действующим последним согласием. Email, дата рождения и представитель не передаются. Несовершеннолетний доступен в поиске только уже подтверждённому тренеру; первоначальный запрос по известному email сохранён.

- `GET /api/v1/coach-athlete-directory/?search=...` — только назначенная активная роль `coach`, лимит 20 запросов в минуту.
- `POST /api/v1/coach-athlete-directory/` — `{athlete, discipline, search}`, повторная проверка доступности/согласия под блокировкой пользователя; блокировка назначения тренерской роли. Повтор не создаёт вторую связь. Ответ 202 содержит русское подтверждение, а не пустое тело.
- Запрос не даёт права на отчёты или заявки. Права возникают после подтверждения спортсменом и ограничены дисциплиной; приостановление/завершение их прекращает.

## Журналы

`GET /api/v1/coach-links/{id}/history/` возвращает время, активную роль, действие и прежние/новые значения. Только спортсмен-владелец или тренер этой связи; чужой ID возвращает 404. Экран «Журнал связей» загружает записи после открытия «История изменений». Там видны запрос, решение, смена статуса и причина.

В `/qualifications` под номером приказа разряда или категории раскрывается существующий ledger `qualification-history/{rank|category}/{id}/corrections/`. Показаны даты, приказ до/после и причина. Исправление федерацией не удаляет прежние реквизиты. Запросы истории отменяются при размонтировании, а содержимое страницы связей пересоздаётся при смене пользователя/активной роли.

## Проверки и делегирование

`tests.test_mandatory_workflows` проверяет минимальный состав данных, действующее согласие, minor/role scope, повторный запрос, права обоих владельцев и отказ постороннему. В финальный backend-набор входят 139 тестов; журнал — `docs/evidence/mandatory-2026-10-28/backend-139.txt`.

`frontend/tests/coach-history-live.spec.ts` регистрирует вымышленного взрослого, выполняет поиск → запрос → подтверждение → приостановление → журнал обоих владельцев. Дополнительно проверяет ledger исправления федерацией. Первый сценарий выполняет keyboard/axe/overflow проверки и снимки 1440/768/390 × light/dark. Отдельный прогон после исправлений: 2 passed, 25.0s. Повторные исправления используют уникальную причину, чтобы прежние записи истории не делали locator неоднозначным.

Для ограниченного ревью контракта был вызван реально обнаруженный MCP `review_code`: разрешены только предложения по directory/history, без записи файлов и передачи секретов. Инструмент вернул ответ с настроенной моделью `gpt-6-luna`; это не объявляется выполнением кода моделью DeepSeek. Интегратор проверил предложения: добавил ограничение частоты, блокировку назначения роли и повторную проверку согласия под блокировкой пользователя. IDOR уже ограничен queryset владельца и проверен тестом. Предшествующий `implement_task` завершился `provider_http_503` и не дал реализации.
