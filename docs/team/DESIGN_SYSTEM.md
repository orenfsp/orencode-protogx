# Визуальный контракт

Авторитетный источник — [docs/design/fsp-reference.html](../design/fsp-reference.html), не редактировать. `frontend/src/app/globals.css` содержит извлечённые CSS правила и токены; `app.css` добавляет стили работающих форм и экранов. `AppShell.tsx` реализует общую композицию. Глобальные токены и общие примитивы меняет только руководитель после согласования. Новые экраны продолжают уже созданную систему.

| Токен/паттерн | Светлая тема | Тёмная тема |
| --- | --- | --- |
| `--paper`, `--ink`, `--mut` | `#fff`, `#1B1C21`, `#5C5C66` | `#1C1B45`, `#F2F2FA`, `#A9A8CC` |
| `--side`, `--side-mut` | `#221F73`, `#C9C7F5` | `#0B0A24`, `#A9A8CC` |
| `--ac`, `--ach`, `--acs` | `#221F73`, `#3A36A8`, `#EEEDF9` | `#A6A3FF`, `#C0BEFF`, `#2A2970` |
| `--sg` | `#FF9900` | `#FF9900` |
| `--rl`, `--rl2`, `--fcs` | `#DDDDE8`, `#9A99B8`, `#221F73` | `#34336E`, `#5A59A0`, `#FF9900` |

Шрифты: `Rubik` для бренда/заголовков, `Inter` для текста/контролов, `JetBrains Mono` для номеров, счётчиков и табличных цифр. `layout.tsx` подключает Google Fonts; в сети без доступа к ним сработают указанные CSS fallback, что может изменить screenshot. Сильная прямоугольная геометрия, видимые обводки 1–2 px, пунктирные разделители, минимум скругления. Кнопка `.btn.p` оранжевая, `.btn.i` индиго, обе с твёрдой тенью смещения 3 px и активным сдвигом. Клавиатурный `:focus-visible` — 3 px. Не добавляйте pill controls, градиенты, glassmorphism или новую палитру.

## Состав экрана

- `.lay` на desktop: боковая колонка `268px`; `.idx` — индиго, навигация с номерами и пунктирными границами, оранжевый маркер активного пункта.
- `.main::before` — вертикальная «документная» рейка `48px` с повторяющимися отверстиями; `.main` оставляет место слева для неё. `.blk` строит заголовок блока в левой колонке `150px`, содержание справа.
- `.bd` — наклонённый «штамп» с двойной/акцентной рамкой для статусов, `.tw` оборачивает таблицу с явными границами. `.pag` существует в референсе как визуальный паттерн; общего работающего pagination-компонента в приложении пока нет.
- `.lb`, `.inp`, `.hint`, `.note.wn` задают подпись, подчёркнутое поле, пояснение и ошибку. Формы Phase 2 повторяют геометрию через `.workflow-form`, `.workflow-fieldset`, `.workflow-actions` в `app.css`. Проверка ввода остаётся на сервере.
- Отступы следуют референсу: крупный padding героя, раздельные блоки с нижней границей, 12–16 px между контролами, ≥44 px интерактивная высота. Точные значения для нового примитива берите из HTML/CSS, не из догадки.
- При `max-width:900px` sidebar исчезает, `.main` получает узкую рейку `26px`, появляется фиксированная `.mobtab` с четырьмя пунктами и мобильные theme/role controls. При `520px` метрики становятся одной колонкой; формы workflow дополнительно переходят в одну колонку при `650px`. Таблицы Phase 2 остаются доступными через горизонтальную прокрутку.

## Проверка изменения

1. До фронтенд-правки прочтите сам HTML и [visual-qa.md](../design/visual-qa.md). Не меняйте эталонный файл.
2. `python scripts/check_design_contract.py` должен дать `PASS`: он проверяет SHA-256 референса и точное соответствие извлечённого CSS.
3. При работающем Compose выполните `npm.cmd run visual:qa` и/или `npm.cmd run visual:phase2` в `frontend/` (Chrome обязателен), сравните релевантные пары при 1440/768/390 px и обеих темах; проверьте desktop sidebar, rail, штампы, таблицу, focus, мобильную навигацию и отсутствие обрезки.
4. Запишите осмотр и обоснованные отличия в `docs/design/visual-qa.md` по разрешению владельца. Одни только успешно созданные PNG не доказывают визуального совпадения.

Reference HTML представляет стиль, а не готовые продуктовые данные и не официальную символику федерации.
