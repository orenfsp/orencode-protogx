# Git workflow

## Состояние текущей интеграции

Локальная интеграционная ветка: `codex/integrate-optional-d1-d12`, HEAD `0c43b000983e15842d6cc08a525341e7deb84670`. Ветка объединяет локальный обязательный сценарий с `feat/case-optional-d1-d12` из ProtoGX. Remote `origin`: `https://github.com/KAIROS-2000/ProtoGX.git`. Локальная интеграция не означает, что она опубликована или принята в `main`; проверяйте фактический remote и статус перед работой.

```powershell
git status --short --branch
git branch -vv
git remote -v
```

## Работа над новой задачей

Руководитель задаёт base commit, разрешённые пути и контракт задачи. Одна задача — одна ветка — один владелец файлов. Перед началом проверьте незакоммиченные изменения и не включайте чужую работу.

```powershell
git switch -c task/FSP-123-short-name
git status --short
```

Добавляйте в индекс только явно разрешённые файлы. Не коммитьте `.env`, токены, персональные данные, `node_modules`, `.next`, локальные БД или generated dependencies.

```powershell
git diff --check
git diff --stat
git add -- <разрешённые-пути>
git diff --cached --stat
git commit -m "docs: explain FSP-123 onboarding step"
```

Перед merge нужны проверки и review по [integration checklist](INTEGRATION_CHECKLIST.md). Не делайте force push или reset общей ветки. Публикацию и создание PR выполняйте только после проверки целевой ветки и правил ProtoGX.

## Обновление ветки и конфликты

Сохраните собственную работу и убедитесь, что remote и целевая ветка верны, прежде чем выполнять fetch/merge. Разрешайте конфликты с учётом обеих версий и владельцев общих контрактов; не выбирайте вслепую `ours/theirs`. После разрешения повторите API, permissions и визуальные проверки затронутой области. Если безопасно разрешить конфликт нельзя, отмените локальное слияние через `git merge --abort` и передайте его руководителю.

## Восстановление

| Ситуация | Действие |
| --- | --- |
| Не тот файл добавлен в index | `git restore --staged -- <file>`; рабочая копия сохранится |
| Локальная правка больше не нужна | Сначала `git diff -- <file>`, затем осознанно `git restore -- <file>` |
| Неудачное локальное слияние | `git merge --abort`, затем проверьте `git status` |
| Потерян указатель на commit | Найдите hash через `git reflog`; согласуйте восстановление до изменения общей истории |
| Ошибочный commit уже опубликован | Согласуйте исправление новым commit или `git revert`; не переписывайте общую историю |

Руководитель принимает интеграцию после handoff по [TASK_TEMPLATE.md](TASK_TEMPLATE.md) и сверки с [TEAM_ROLES.md](TEAM_ROLES.md). Условия CI и защиты веток описаны в [CI.md](../CI.md).
